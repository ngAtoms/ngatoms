Grid

A data grid for large, structured data: hierarchical rows, single or multi-level column headers, pinned columns, number formatting, filters, sorting, cell editing, and virtualization on both axes. The app owns the data — the grid displays what it is given and applies no business rules.

Usage

Add the grid to your project. Its models, grid-core, and the shared overlay helpers come along automatically.

$ ngatoms add grid

Then import into your component:

Simple headers

Groups, pinning and hierarchy are all optional. A plain list of leaf columns gives a single header row, which is all a list, a lookup or a log needs.

As a plain table

For a short list the grid can behave like an ordinary table. fitRows makes it as tall as its rows, with no vertical scrolling. A column with flex takes the width the others leave free, so the table always fills its container, and wrap lets long text run onto as many lines as rowHeight fits, with the full text as a tooltip. The API tables further down this page, and on every other page of these docs, are this.

Filters and sorting

Give a column a filter and its header shows a filter button: text and number offer conditions, set lists the distinct values to tick. Mark it sortable and clicking the header cycles ascending, descending, unsorted. Both are models, so the app can read, persist and restore them. Try the Product filter on the grid at the top: in a tree, the ancestors of a match stay visible, dimmed, and sorting orders siblings within each parent.

Filtering on the server

By default the grid filters and sorts the rows it holds. With filterMode="external" or sortMode="external" it only shows the controls and reports the change; the app fetches and passes new rows in. Use it when the data is paged. Filtering never recalculates a value: a parent keeps the total it was given. To show totals for the filtered rows, use external mode and return them.

Editing

Mark a column editable and its cells accept input: type to replace, Enter (Return on a Mac) or F2 to edit, double-click works too. Enter commits and moves down, Tab commits and moves right, Escape cancels, Delete clears. The grid never changes your data. It emits (cellsChange); the app applies it, runs whatever rules it has, and passes the rows back — here the app recomputes the group and total rows. [cellState] decides what each cell is: January and February are locked, totals are calculated, edited cells are dirty, and a negative value is invalid.

Selection, copy and paste

Drag, Shift+click or Shift+arrows select a block. Shift+Space selects the row and Ctrl+Space selects the column; on a Mac the column shortcut stays Ctrl+Space, because ⌘Space belongs to the system. Ctrl+A (⌘A on a Mac) selects everything and Escape goes back to one cell. Ctrl+C (⌘C) copies the block as tab-separated text, which is what spreadsheets read and write, and Ctrl+V (⌘V) pastes one: a single value fills the selection, and a block is laid out from its top-left corner. A larger block is not repeated. Delete clears the block, Ctrl+X (⌘X) cuts it, Ctrl+D (⌘D) fills the first row down, and Ctrl+Enter (⌘Return) gives the whole block the value of the active cell. Each of these is one (cellsChange) batch. Ctrl+Z and Ctrl+Y (⌘Z and ⌘Y) emit the opposite batch as an ordinary change, so undo goes through the same rules as an edit. Try it on the grid above: the line under it sums the selection, which the app works out from (selectionChange). Pasted values that a cell cannot take are skipped and reported through (cellsRejected). One operation touches at most 200,000 cells; a larger one is not carried out, and (batchRejected) says so.

Rows and hierarchy

Rows are a flat list. Each row has an id, your record in data, and an optional parentId. The column marked tree: true shows the indentation and the expand toggle, and [(expanded)] holds the open rows. Set kind to subtotal or total to style a row; the grid never computes one.

Column groups and pinning

Columns are a tree: a group spans its children, to any depth. Leaf columns can be pinned left or right; pinned columns stay in view while the rest scrolls, and only the columns in view are rendered.

Number formatting

A format is declarative and display-only. Set it on a column, and override it on a row when the row dictates the format — the Return rate line at the top is a percentage in every column. A column flagged variance is colored by the row's favorable direction: more returns than the target is bad news, more sales than the target is good news.

Custom cells and editors

A cell shows text by default. Give the grid an ngaGridCell template for a column and its cells show your markup instead — a badge, a link, a control that is always there, like the checkbox here. An ngaGridEditor template replaces the built-in text field while a cell is edited: put any control in it, a dropdown, a date picker, your own component. It receives the value and a commit function; committing emits (cellsChange) like any other edit, so undo and your rules apply the same way. Keys typed in your controls stay with them, and Escape closes the editor. Here Status opens an nga-select and Due an nga-date-picker: press Enter or double-click.

Reordering rows

With rowReorder each row gets a handle. Drag it between two rows to move the row there, or onto the middle of a row to make it a child of that row; Alt+↑ and Alt+↓ (⌥↑ and ⌥↓ on a Mac) do it from the keyboard. The grid does not move anything. It emits (rowMove) with the row, the row it was dropped on and the position, and the app moves the row in its data — try it on the task list above. A row cannot be dropped into its own branch. Handles are hidden while the grid is sorting the rows, since their order is then not yours to set.

Column width

Drag the edge of a header to resize a column, or double-click it to fit the header and the cells on screen. Widths live in [(columnWidths)], by column id, so the app can save and restore them. A column never goes below its minWidth, and resizable: false takes the handle away. To hide a column without rebuilding the column tree, set hidden.

Paging by scroll

When the data is too large to load at once, tell the grid how big it is with rowCount and pass in the rows you have. Each row carries its index in the full result; positions without a row show a placeholder. (visibleRangeChange) reports what is on screen, and the app loads the pages it is missing. This list has 50,000 orders on a mock server that answers 100 at a time. Filtering and sorting are the server's job in this mode: use the external modes.

Loading children on demand

A row with hasChildren: true shows the expand toggle before its children exist. Expanding it emits (rowExpand); the app loads the children and adds them to the rows with the right parentId. Until they arrive the row shows placeholder rows under it. If a row turns out to have no children, set its hasChildren back to false.

Export

exportText() returns the rows on show as CSV: every visible column, one header line, collapsed and filtered-out rows left out. Grouped columns get their full path as header, so two months of different quarters stay distinct. Values are written raw by default, which other programs read back unchanged; ask for formatted to write them as the grid shows them. What to do with the text — download it, upload it, copy it — is up to the app.

Keyboard shortcuts

Everything the grid does with the mouse it also does from the keyboard. Wherever a shortcut uses Ctrl, a Mac uses ⌘, and Alt is ⌥; keys a Mac laptop does not have are reached with Fn. Filter the list by group from the header.

Density

compact is the default and suits dense data. comfortable gives rows more room. On touch screens the grid uses the comfortable row height whatever the setting, so rows and header controls stay easy to hit.

Scale

Rows and columns are both virtualized, so the DOM holds only what is on screen. This grid has 100,000 rows and 500 columns — fifty million cells — with every row expanded.
