Grid

A data grid for large, structured data: hierarchical rows, multi-level column headers, pinned panes, number formatting, filters, sorting, and virtualization on both axes. The app owns the data — the grid displays what it is given and applies no business rules.

Usage

The grid is in development and not in the registry yet. This page documents what is built so far: read-only rendering, filters and sorting. Editing comes next.

Simple headers

Groups, pinning and hierarchy are all optional. A plain list of leaf columns gives a single header row, which is all a ledger, a lookup or an audit list needs.

Filters and sorting

Give a column a filter and its header shows a filter button: text and number offer conditions, set lists the distinct values to tick. Mark it sortable and clicking the header cycles ascending, descending, unsorted. Both are models, so the app can read, persist and restore them. Try the Account filter on the income statement at the top: in a tree, the ancestors of a match stay visible, dimmed, and sorting orders siblings within each parent.

Filtering on the server

By default the grid filters and sorts the rows it holds. With filterMode="external" or sortMode="external" it only shows the controls and reports the change; the app fetches and passes new rows in. Use it when the data is paged. Filtering never recalculates a value: a parent keeps the total it was given. To show totals for the filtered rows, use external mode and return them.

Rows and hierarchy

Rows are a flat list. Each row has an id, your record in data, and an optional parentId. The column marked tree: true shows the indentation and the expand toggle, and [(expanded)] holds the open rows. Set kind to subtotal or total to style a row; the grid never computes one.

Column groups and pinning

Columns are a tree: a group spans its children, to any depth. Leaf columns can be pinned left or right; pinned columns stay in view while the rest scrolls, and only the columns in view are rendered.

Number formatting

A format is declarative and display-only. Set it on a column, and override it on a row when the row dictates the format — the Operating margin line above is a percentage in every column. A column flagged variance is colored by the row's favorable direction: spending over budget is bad news, revenue over budget is good news.

Density

compact is the default and suits dense reports. comfortable gives rows more room.

Scale

Rows and columns are both virtualized, so the DOM holds only what is on screen. This grid has 100,000 rows and 500 columns — fifty million cells — with every row expanded.
